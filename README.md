# Student Feedback Summarizer

[![Built with askThili](https://ask.thili.ai/api/v1/public/projects/8qjscrn2as/badge.svg)](https://ask.thili.ai/b/8qjscrn2as)

The Student Feedback Summarizer is an EdTech tool designed for course instructors. It leverages LoRA fine-tuning to adapt a language model to generate concise summaries of student comments, streamlining the process of curriculum improvement.

## What you are building

**Goal.** You will build a tool that fine-tunes a language model with LoRA on course feedback, generating concise summaries of student comments to aid rapid curriculum improvement.

**Done when.** The project is done when you have successfully fine-tuned a pre-trained LLM using the LoRA technique, and your Streamlit UI can accept student feedback, trigger summarization, and output relevant summaries that demonstrate the model's adaptation.

## Milestones

Tick these off as you go, and commit after each one.

- [x] **1. Prepare a small dataset of synthetic student feedback and summary pairs.**  
      Hint: Focus on creating diverse, representative examples for your dataset.
- [x] **2. Implement LoRA adapter injection and training on a pre-trained LLM (e.g., GPT-2).**  
      Hint: Use the `lfllm-lflora` technique to inject and train the LoRA adapter.
- [ ] **3. Develop a Streamlit UI to upload feedback and trigger summarization.**  
      Hint: Design a simple Streamlit interface for inputting feedback and displaying summaries.
- [ ] **4. Evaluate the quality of generated summaries against original feedback.**  
      Hint: Consider metrics like ROUGE or manual inspection for evaluating summary quality.
- [ ] **5. Implement adapter merging for inference.**  
      Hint: Apply the `lfllm-lflora` merging technique to integrate the adapter for efficient inference.

## Run it

You need Python 3.12 and git.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then choose a model; see the comments inside
streamlit run app/main.py
pytest
```

Your work goes in `app/core.py` (one stub per milestone) and `tests/test_core.py`. The first tests pass already; they
check the plumbing.

## Settings and secrets

Model settings live in `.env`, which is ignored by git. **Never commit `.env` or paste a key into code.** If a key ever
reaches GitHub, treat it as leaked and make a new one.
